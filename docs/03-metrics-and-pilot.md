# Метрики и дизайн пилота

> **Статус:** ранняя схема. Канонический экспериментальный дизайн — three-arm store-cluster RCT из [итоговой концепции](00-final-concept.md) и [профильного отчёта](research/07-pilot-plan.md).

## Что задано кейсодателем

### Основная продуктовая метрика реального пилота

- Рост доли пользователей, которые совершают не менее N покупок за период; **или**
- рост среднего числа покупок в тестовой группе относительно контрольной.

Эффект должен достигаться без снижения маржи на участника. Нельзя просто раздать много баллов и искусственно поднять частоту покупок.

### Критерии хакатона

- **Персонализация:** hit rate персонального челленджа ≥ 70% на 30–50 синтетических профилях.
- **Экономика:** стоимость награды ≤ ожидаемый прирост маржи.
- **Антифрод:** Precision важнее Recall — лучше пропустить часть мошенников, чем блокировать нормальных покупателей; порог должен быть объяснимым.
- **Бизнес-эффект:** симуляция на 1–10 тыс. пользователей должна показать потенциальный рост частоты покупок или маржи.

## Цепочка метрик для презентации

1. **North Star:** Purchases per User / Month ↑.
2. **Retention:** доля пользователей с ≥ N покупками ↑.
3. **Engagement:** completion rate челленджей ↑.
4. **AI quality:** Challenge Hit Rate ≥ 70%.
5. **Economics:** Incremental Margin − Reward Cost > 0.
6. **Safety:** Fraud Precision высокий, False Positive Rate низкий.

Итоговая метрика, связывающая AI, игровые механики и бизнес X5:

```text
ROI геймификации =
    (дополнительная маржа от покупок − стоимость наград)
    / стоимость наград
```

## Что в кейсе не определено

В исходном диалоге после вопроса «метрики есть?» был задан уточняющий вопрос: «как это измерять не данно?». Ответ: точная методика измерения в кейсе не задана. Не определены:

- период наблюдения;
- значение N покупок;
- длительность эксперимента;
- точная формула uplift;
- формальное определение успешного `hit` для AI-челленджа.

Команда должна самостоятельно предложить экспериментальный дизайн.

## Предлагаемый A/B-тест

Схожих пользователей случайно делят на две группы:

- **Control:** обычное приложение без нового игрового слоя;
- **Test:** персональные челленджи, аватар и рейтинг.

### Частота покупок

```text
Purchase Frequency =
    число покупок / число пользователей за период
```

```text
Uplift =
    (Purchase Frequency Test − Purchase Frequency Control)
    / Purchase Frequency Control
```

Пример:

- Control — 4,0 покупки в месяц;
- Test — 4,3 покупки в месяц;
- uplift = `(4,3 − 4,0) / 4,0 = 7,5%`.

### Доля пользователей с ≥ N покупками

Пример допущения: `N = 4` покупки за 30 дней.

- Control: 40% пользователей сделали ≥ 4 покупок;
- Test: 44%;
- абсолютный uplift = `+4 п. п.`.

## Экономика наград

Частоты покупок недостаточно: рост может быть куплен чрезмерными бонусами. Параллельно считается чистая дополнительная маржа:

```text
Incremental Margin per User =
    Margin(Test) − Margin(Control) − Cost of Rewards
```

Условие успеха:

```text
Incremental Margin > 0
```

Первый пример из исходника:

- дополнительная маржа от новых покупок — 50 ₽ на пользователя;
- игровые награды — 30 ₽;
- эффект — `+20 ₽` на пользователя.

Второй пример из аналитического разбора:

- без игры пользователь приносил 500 ₽ маржи в месяц;
- с игрой — 545 ₽;
- награды стоят 20 ₽;
- `545 − 500 − 20 = +25 ₽` на пользователя.

## Что требуется доказать аналитикой

Логика доказательства из исходного разбора:

```text
AI выбрал пользователю подходящую механику
                         ↓
пользователь выполнил челлендж
                         ↓
пользователь сделал дополнительную покупку
                         ↓
X5 получила дополнительную маржу
                         ↓
маржа > стоимости награды
```

Ключевая формула в этой формулировке:

```text
Net Incremental Margin =
    Margin Test − Margin Control − Reward Cost
```

## Оценка качества AI-челленджей

В исходнике присутствуют два совместимых примера проверки.

### Вариант 1. Простая экспертная проверка

Для 30–50 синтетических профилей эксперт оценивает, соответствует ли челлендж истории покупок. Если подходящими признаны 38 из 50:

```text
Hit Rate = 38 / 50 = 76%
```

Порог кейса ≥ 70% пройден.

### Вариант 2. Трёхуровневая шкала

Для 50 профилей AI предлагает по одному челленджу, после чего эксперт ставит оценку:

- `2` — релевантный;
- `1` — допустимый;
- `0` — нерелевантный.

`hit = 1`, если оценка ≥ 1.

```text
Hit Rate = Relevant Challenges / All Challenges
```

Пример: `39 / 50 = 78%`, критерий выполнен.
